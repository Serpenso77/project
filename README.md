# Lemash

Рабочий демонстрационный интернет-магазин носков для России: самостоятельный дизайн, адаптивная витрина, SVG-иллюстрации товаров и текстовый логотип. Каталог содержит 38 товаров после объединения 19 артикулов Яндекс Маркета и 30 товаров Ozon; 11 точных совпадений артикулов объединены. Снимок Ozon получен 23.10.2026, исходный XLSX Маркета — от 22.10.2026. Цены указаны на дату соответствующего источника. Оформление и доставка остаются демонстрационными.

## Запуск

Нужен Node.js >= 22.13 с встроенным `node:sqlite` (проверено на Node.js 24.19). Внешних npm-зависимостей нет.

```sh
cd /workspace/project
npm start
```

Сервер слушает порт 3000. `PORT` меняет порт, `DATA_DIR` — каталог SQLite (по умолчанию `.data`). `COOKIE_SECURE=true` включайте при обслуживании через HTTPS. Каталог базы не публикуется HTTP-сервером. Нужны постоянный диск и резервные копии для сохранения данных между развёртываниями. Запущенный процесс не переносится в новую среду автоматически.

```sh
npm test
```

Проверяются выдача каталога, регистрация и вход, ошибочный пароль, создание и серверный пересчёт заказа, бесплатная доставка, валидация, изоляция заказов между пользователями и блокировка запросов с другого origin. База тестов временная.

## Реализовано

- Каталог: категории, поиск, сортировка, карточка товара с полным описанием, характеристиками и фотогалереей. Размеры и составы из Ozon добавлены по фактическим атрибутам; неизвестные размеры оставлены неизвестными.
- Избранное и корзина: локальное сохранение, изменение количества, удаление.
- Кабинет: регистрация, вход/выход, история собственных заказов, избранное.
- SQLite: пользователи, сессии и заказы; пароли через scrypt, HttpOnly/SameSite cookie.
- Оформление: валидация контактов, серверные цены и доставка, согласие, подтверждение заказа.
- Адаптивные страницы, информация о доставке, оплате и данных.

Регистрация не проверяет владение email. Восстановление пароля, рассылки, коммерческие документы, оплата, реальные тарифы/ПВЗ, остатки и кабинет продавца не реализованы. Демонстрационные заказы не передаются продавцу или в доставку. Нельзя принимать реальные продажи в текущем режиме.

## Подключение реальных продаж

1. **Каталог.** Импортированы 19 SKU из предоставленного XLSX: названия, полные описания, цены, прежние цены и заполненные публичные характеристики. Каталог находится в `data/catalog.json`, оригиналы фото — в `public/images/`. Нужны явные размеры, остатки и правила обновления цен. Производственную версию необходимо перевести на управляемый каталог и складской учёт. Импорт API — отдельная интеграция, ключи нельзя отдавать браузеру.
2. **ЮKassa.** Нужны договор продавца, shopId и серверный ключ в защищённом хранилище развёртывания. Сервер создаёт платёж по сохранённому заказу с ключом идемпотентности. Возврат из формы оплаты сам по себе не подтверждает оплату: нужно проверять статус через API и обработку уведомлений, сохранять переходы статусов, предотвращать повторное списание и выполнять возвраты. Фискализация/чеки настраиваются под систему налогообложения и реквизиты продавца. Интеграция ещё не написана.
3. **СДЭК.** Нужны договор и серверные учётные данные, адрес отправления, габариты и вес каждого товара. Требуются выбор настоящего ПВЗ, актуальный серверный расчёт тарифа и срока, создание отправления после подтверждения заказа, этикетки и отслеживание. Текущие 350 ₽/бесплатно — демонстрационный расчёт, не API СДЭК.
4. **Кабинет.** Подключить подтверждение email и восстановление пароля с ограниченными по времени одноразовыми токенами, почтовый сервис, защиту от перебора, управление профилем, удаление данных и уведомления о статусе. Нужен защищённый кабинет продавца для обработки заказов и остатков.
5. **Юридические сведения.** Добавить ИП/ООО, ИНН/ОГРН, контакты, публичную оферту, действительные условия доставки, возвратов, политику обработки данных и необходимые согласия. Уточнить применимость маркировки «Честный знак», фискализации и требования к размещению персональных данных с профильными специалистами.
6. **Развёртывание.** Домен, HTTPS, резервные копии SQLite, мониторинг, ограничение запросов/авторизации, защищённое хранение ключей, реальная проверка оплаты/возврата и доставки в тестовых средах провайдеров. После этого — контрольный заказ и коммерческий запуск.

Реквизиты и ключи передаются через защищённые настройки среды, не через чат или репозиторий. Никаких ключей для реальных провайдеров в этом проекте сейчас нет.

## Основа дизайна

Молочный фон, графитовый текст, терракотовые акценты, хвойные и песочные оттенки. Словесный логотип `lemashki●`. В каталоге используются реальные фотографии из выгрузки. Ранее созданные SVG-иллюстрации сохранены в коде как резерв для старых демонстрационных данных. Пример nosmag.ru был недоступен (HTTP 403), его дизайн и содержимое не копировались. Исходный `test.html` сохранён; в новом сервере этот адрес открывает актуальную витрину.

## Импорт выгрузки от 22.10.2026

`data/import-report.json` фиксирует результат: 19 уникальных артикулов, 326 ссылок на изображения, 123 уникальных скачанных оригинала, 0 ошибок загрузки. В каждой карточке сохранены исходное HTML-описание (`sourceDescriptionHtml`) и полный безопасный текст для отображения. HTML из файла не исполняется. Внутренние поля продавца (себестоимость, расходы, ошибки и рейтинг карточки) не публикуются.

Артикулы не объединяются автоматически: одинаковые названия не доказывают одинаковый размер или вариант. Размеры, доступное количество и процентный состав в отдельных полях отсутствуют. В тестовом заказе используется явный режим «По артикулу», а покупатель видит, что размер нужно уточнить. Старые демонстрационные записи заказов сохраняются; несовместимые позиции локальной корзины отфильтровываются при загрузке.

Импорт можно повторить с помощью Python 3 и openpyxl (нужны только для импорта, не для запуска магазина):

```sh
python3 scripts/import_catalog.py '/путь/к/выгрузке.xlsx'
```

Загрузчик работает только с HTTPS-изображениями с `avatars.mds.yandex.net`, проверяет формат и размер, сохраняет оригиналы с именами на основе SHA-256 URL и повторно использует уже скачанные файлы. Запускать импорт следует из доверенной выгрузки владельца; обновление каталога и цен проверять перед коммерческим использованием. Для другой даты выгрузки необходимо обновить дату источника в импортёре и подписи витрины.

Проверено: все 19 названий, SKU, цен, полных исходных описаний и 326 ссылок совпадают с XLSX. Автотесты сервера проверяют 19 товаров и наличие локальных фото. Браузерная проверка включает все карточки и переключение галерей, категории, поиск по артикулу, корзину и тестовый заказ.

## Экспорт Ozon Seller API

Добавлен автономный скрипт `scripts/export_ozon.py` (Python, без сторонних зависимостей) для сохранения доступных через Seller API данных каталога, описаний, характеристик, цен, остатков и медиа. Инструкция, формат выгрузки, безопасное подключение ключей и ограничения: [scripts/OZON_EXPORT.md](scripts/OZON_EXPORT.md). Запуск: `npm run export:ozon`, тесты: `npm run test:ozon`. Текущий каталог сайта не меняется при экспорте. Живой экспорт через авторизованный Seller API выполнен успешно: 30 товаров, 175 фотографий и 14 видео. Ключи хранятся в защищённых настройках среды.

## Ozon: завершённый живой импорт, 23.10.2026

- Приватная полная выгрузка: `.data/ozon-export-live/`, статус `complete`, нет пропусков информации, описаний, характеристик, цен или остатков по всем 30 товарам.
- Скачаны 189 медиафайлов: 175 фотографий JPEG и 14 видео MP4. Временный сбой DNS одного изображения устранён повторной загрузкой. В скрипт добавлены повторы временных ошибок медиа, проверка сохранённых файлов не требует сетевого DNS-запроса.
- Исходная база Маркета сохранена в `data/yandex-catalog.json`. Отчёт объединения — `data/ozon-import-report.json`. 11 совпадений объединены **только по точному seller SKU**, 19 новых артикулов добавлены; итог 38 товаров. Включены ножницы для рукоделия из кабинета продавца, для них выделена категория.
- Полные исходные описания обеих площадок сохранены. Основной текст Маркета остаётся основным для прежних товаров, отдельное описание Ozon доступно в раскрывающемся блоке. Фотографии объединены, видео доступны в карточках, HTTP Range поддерживает воспроизведение и перемотку.
- Для всех 29 носочных артикулов Ozon есть размеры. Несколько размеров обуви из одного SKU отображаются как единый вариант, например «37 / 38»; независимые складские остатки для каждого размера не выдумываются. Ножницам размер не требуется. Для 8 артикулов только из Маркета размер по-прежнему неизвестен.
- Для существующих товаров цены сайта и ID сохранены. Цена Ozon хранится отдельно и отображается с источником/датой. Для новых товаров исходной ценой служит цена продавца из Ozon API. Остатки Ozon — отдельный снимок, не обещание доступности для заказа напрямую на сайте.
- В `data/catalog.json` не публикуются себестоимость (`net_price`), комиссии и данные авторизации. Исходные ответы со всеми полями продавца остаются вне `public/` и исключены из Git.

Повторное обновление выполняется осознанно: свежий экспорт через `python3 scripts/export_ozon.py --refresh`, затем `python3 scripts/import_ozon_catalog.py --export <папка-завершённой-выгрузки>`. Указывайте фактическую папку экспорта: проверенный текущий снимок находится в `.data/ozon-export-live`, тогда как стандартная папка экспортёра — `.data/ozon-export`. Импортёр требует статус `complete`, проверяет SHA-256 медиа, сохраняет прежние ID и не меняет данные заказов. Для пользовательской даты снимка поддержан `--source-date YYYY-MM-DD`; по умолчанию применяется дата ответа в Europe/Moscow.

Проверено 5 серверных тестов и 21 Python-тест экспорта/импорта. В браузере проверены все 38 карточек, исходные описания обеих площадок, галереи, размеры, воспроизведение видео, категория рукоделия, регистрация и тестовый заказ нового товара Ozon, мобильная ширина. При повторном импорте одинакового снимка каталог и список файлов остаются неизменными.

## GitHub и запуск магазина

GitHub хранит исходники, публичный каталог и медиа. Workflow `.github/workflows/checks.yml` запускает серверные и Python-тесты при push и pull request без ключей маркетплейсов. Действительные ключи, SQLite и приватные выгрузки исключены через `.gitignore`.

GitHub Pages не подходит для полного магазина: этот проект требует Node.js и постоянного диска для SQLite. Для работы с покупателями репозиторий нужно подключить к серверу/платформе развёртывания с Node.js 24, HTTPS и резервным копированием `.data`. Команда запуска `npm start`, порт определяется `PORT`. Ключи и переменные задаются в защищённых настройках хостинга. Во время развёртывания не запускайте экспорт/импорт автоматически: опубликованный каталог уже включён в репозиторий.

Текущие фото и видео включены в репозиторий для воспроизводимого запуска. При росте ассортимента их следует перенести в объектное хранилище/CDN. Пользовательские заказы и аккаунты не должны храниться в GitHub; им нужны база и резервные копии.
